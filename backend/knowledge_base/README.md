# Engineering Handbook

This handbook defines the engineering standards and recommended development practices used by the example engineering organization.

It is designed to give software engineers a consistent reference for building, reviewing, testing, securing, deploying, and operating software.

## Purpose

The handbook aims to:

- establish consistent engineering practices across teams;
- improve software quality, security, reliability, and maintainability;
- make engineering expectations easy to discover;
- reduce avoidable differences between projects;
- provide a shared reference during design and code reviews.

## How to use this handbook

Requirements use the following terms:

- **MUST** — mandatory requirement.
- **MUST NOT** — prohibited practice.
- **SHOULD** — recommended unless there is a justified reason not to follow it.
- **SHOULD NOT** — generally discouraged.
- **MAY** — optional practice.

When a project cannot comply with a mandatory standard, the team must document the exception, its rationale, associated risks, and any compensating controls.
